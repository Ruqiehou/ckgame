## WebUI 实施计划（无地图，信息面板 + 基础操作）

基于现有引擎层 `GameAPI`（`snapshot()` / `action()` 已含全部所需数据），在已声明的 `ck_engine/web/` 占位下补齐实现。纯标准库（`http.server`），零第三方依赖，与项目一致。

### 新建文件

**1. `ck_engine/web/server.py` — HTTP 服务器（核心）**
- `CKWebServer` 类：构造时创建单个 `GameAPI(scenario)`（默认 1066），内部用 `ThreadingHTTPServer` + `BaseHTTPRequestHandler` 子类。
- 路由：
  - `GET /` → 返回 `static/index.html`
  - `GET /static/<path>` → 从 `ck_engine/web/static/` 读取静态文件（含路径穿越防护）
  - `GET /api/snapshot` → `api.snapshot()` 的 JSON
  - `GET /api/scenarios` → `list_scenarios()` 的 JSON
  - `POST /api/action` → 读取 JSON body 后调用 `api.action(payload)`，返回新快照 JSON
- 关键细节：**JSON 安全化**——快照里含元组（如 `scheme_types`、`council_positions`、`exchange_rates` 的元组键），直接 `json.dumps` 会报错；加一个递归转换函数（元组→列表、元组键→字符串键、集合→列表），并以 `ensure_ascii=False` 输出中文。
- 错误处理：请求体非法返回 400；action 内部异常已被 `GameAPI` 捕获写入 messages，正常返回快照。
- `__main__` 用 `argparse` 支持 `--host`、`--port`（默认 8000）、`--scenario`，启动时打印访问地址。补齐后现有 `ck_engine/web/__init__.py` 的 `from ck_engine.web.server import CKWebServer` 即生效。

**2. `ck_engine/web/static/index.html` + `style.css` + `app.js` — 前端**
- 无地图。单页布局：顶栏 + 卡片区 + 标签页。
- **顶栏**：日期 / 季节 / 回合 tick / 场景；操作按钮：推进时间（1/7/30 天）、存档、读档（存档下拉）、新游戏、切换玩家（可玩统治者下拉）。
- **信息卡片（常驻）**：玩家资金面板（金币、威望、虔诚、压力、健康、收入、兵力、等级/经验、六项属性、法律、战争疲劳）；待处理事件区（标题/描述/选项按钮，置顶醒目）；消息与日志区。
- **标签页**：
  - 人物：全部存活角色表格（姓名/王朝/年龄/头衔/与玩家关系徽章/好感/金币/属性），点击行展开详情
  - 领地：己方省份列表（发展度/控制度/繁荣/税收/建筑/港口），可"开发"按钮
  - 军事：军团列表（兵力/位置）、战争列表
  - 政治：派系与最后通牒（接受/拒绝）、内阁成员与任务、条约、阴谋、宣称、可执行重大决策按钮
  - 玩法：狩猎/养生等玩法目录与状态按钮
  - 家族：配偶与子女
- **前端逻辑**：原生 JS，无 CDN；每 3 秒轮询 `/api/snapshot` 刷新，每次操作后立即刷新；快照数据仅在变化时重渲染对应区域（按 `date+tick` 判断），避免闪烁。
- 界面为中文，与项目语言一致。

**3. `tests/test_web_server.py` — 测试（unittest，与项目一致）**
- 端口 0 启动服务器于线程内，测：`GET /` 返回 200 与 HTML；`GET /api/snapshot` 返回含 `player`/`characters`/`date` 的 JSON；`POST /api/action`（advance 1 天）返回快照且日期变化；`GET /static/app.js` 返回 200。
